# Reproduction and evidence

## Workspace and configuration

Use a disposable checkout with repository-relative paths intact. The scripts may replace CSVs, figures, PDDL and model files at their default paths. Preserve the distributed and submitted copies independently. Run commands from the project root using the Python 3.12 environment in the README. The examples assume that environment's Python is on `PATH`.

Historical scripts use local data files. Live monitoring and market-data refresh use Kite Connect with the following keys in a local `.env` or the current process environment:

```dotenv
KITE_API_KEY=
KITE_API_SECRET=
KITE_ACCESS_TOKEN=
```

The dashboard initiates Kite authentication and can write a refreshed token to `.env`. Use the authorised credentials for your own Kite application when live access is required. Historical dashboard mode still requires a valid session through the normal entry point. Inspect the stored CSV and Markdown reports directly for credential-free review.

## Financial evaluation and historical replay

For a dissertation-period reconstruction, use market data through 31 March 2026 in the disposable copy. If reproducing from the submission ZIP, filter `NIFTY50_spot.csv` and `NIFTY_futures_continuous.csv` to rows with `date <= 2026-03-31`, keeping the headers and other inputs unchanged. The last included market row in both files is 30 March. This cutoff recreated the archived upstream hedge-ratio and daily-return files byte for byte. Using the later rows present in the ZIP changes the final day's forecast availability because the upstream feature frame drops rows without forward labels before shifting the forecasts.

Run:

```text
python -m src.evaluation.run_hedge_performance_backtest
python -m src.evaluation.run_proposal_four_strategy_backtest
```

The upstream script writes `hedge_performance_daily_details.csv` and `hedge_ratio_series.csv`. The four-strategy runner uses these, daily futures closing prices and the numerical planner. It exports period summaries, daily strategy returns, configuration metadata and per-day planner logs. Forecast-derived ratios are shifted before the financial evaluation. The planner nevertheless sizes contracts using the benchmark day's closing futures price where available and uses the resulting ratio in that day's return attribution. Treat the archived result as an end-of-day simulation under those conventions.

Historical replay combines the core and optional DCC-smoothed ratio series, local futures closes, the historical lot-size schedule and regression predictions. The interface can substitute defaults when certain files or predictions are missing. Verify your inputs before interpreting a replay.

## Planner demonstrations and validation

```text
python -m src.planning.run_hedge_planner --demo
python -m src.planning.autonomous_symbolic_planner
python -m src.planning.numerical_planner
python -m src.planning.futures_execution --demo
python -m src.planning.run_planned_futures_execution --demo
```

ENHSP requires a Java runtime on `PATH`. To use independent VAL validation, install or build VAL from its upstream project and set `VAL_VALIDATE` to the trusted validator executable path. The app also searches `tools/val/` for a local executable. Run VAL with the domain, problem and action file as arguments. The checked-in [common-scenario results](../outputs/reports/planning/three_planner_common_scenario_comparison_val.csv) record the original action sequences. Write one lowercase action in parentheses per line, with each arrow-separated action on its own line. [VAL upstream project](https://github.com/KCL-Planning/VAL)

[Planning evidence](evidence/planning/) includes submission copies of the opening, insufficient-margin and roll-then-hold PDDL cases for each planner variant, plus the numerical and autonomous symbolic edge-case summaries. The full archived comparison includes 12 common cases per variant. Output paths in archived tables refer to the original generated hierarchy. Find the selected copies under `docs/evidence/planning/` using the same variant and scenario suffix.
